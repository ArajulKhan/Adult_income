# Adult Income — ML Model + Working CLI Prototype

## Project structure

This project keeps the **original notebook as the Machine Learning / Model Training file**.

```text
adult_income.ipynb          ← ML / model training
adult_income_cli.py         ← Working prototype
README.md                   ← Instructions
one_page_summary.md         ← Project summary

model.pkl                   ← generated by the notebook (example)
scaler.pkl                  ← generated by the notebook (example)
predictions.csv             ← generated by the prototype
```

## 1. Machine Learning file

The original file:

```text
adult_income.ipynb
```

is the ML/model-training part of the project.

It should be run first. It contains the project's original data preparation, feature processing, Logistic Regression training/evaluation, and model saving workflow.

**The notebook is not replaced by the CLI.**

The CLI only uses the trained artifacts produced by the notebook.

## 2. Working prototype

The separate prototype is:

```text
adult_income_cli.py
```

It loads the trained model and makes predictions for new data.

### CSV mode

```bash
python adult_income_cli.py --csv new_people.csv
```

Specify an output file:

```bash
python adult_income_cli.py --csv new_people.csv --output predictions.csv
```

### Interactive mode

```bash
python adult_income_cli.py --interactive
```

The program asks for the feature values for one person and then displays the prediction.

## 3. Expected features

The prototype follows the feature names found/used by the original notebook:

### Numeric features

```text
age, fnlwgt, educational-num, capital-gain, capital-loss, hours-per-week
```

### Categorical features

```text
workclass, education, marital-status, occupation, relationship, race, gender, native-country
```

Target:

```text
income
```

## 6. Important note about the original notebook

This README is intentionally based on the original notebook rather than replacing its ML workflow.

If the original notebook saves the model and scaler separately, the CLI expects those saved artifacts.

If the notebook saves a complete scikit-learn Pipeline instead, the CLI can use that Pipeline directly.

For a separate-model/separate-scaler workflow, the exact categorical encoding used by the notebook must also be available to the prototype if the saved classifier expects already-encoded features.

## 7. Prototype output

For CSV input, the prototype creates:

```text
predictions.csv
```

with the original input columns plus:

```text
predicted_income
```

If the loaded model supports probability prediction, it also adds:

```text
probability_gt_50K
```
